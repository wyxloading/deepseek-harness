# @deepseek-ai/dsh-client-ui-settings-models-refresh

[English](README.md) | 中文

## 概述

本包在「模型」设置页的 DeepSeek 提供方行上增加一个**获取模型列表**动作。它会向该线路当前解析到的端点（既可能是部署自己的代理或网关，也可能是公开 API）询问它提供哪些模型，并打开一个选择器列出端点披露的候选项。在用户确认之前不会写入任何内容：被勾选的候选项会成为该线路的模型目录，而用户已经调整过的行会保留它自己的名称与容量。

<a id="use-this-package"></a>
## 使用本包

打开「设置」，进入**模型**页，使用 DeepSeek 行下方的按钮。点击后会询问该线路当前解析到的端点；端点一旦应答，就会打开对话框列出它披露的每一个模型。

### 选择要配置的内容

列表中的模型默认全部勾选，因为这个动作的目的就是让该线路的目录与端点实际提供的内容一致。取消勾选会让该模型离开已存储的目录；端点不再列出的模型，在确认更新后也会消失。**全选**与**取消全选**只作用于当前搜索结果，而选择为空时更新会被拒绝，因此一次筛选不会悄悄清空目录。

**更新配置**会按端点顺序写入已勾选的模型。该线路原本就有的模型会保留已存储的行——用户编辑过的显示名称与容量会在刷新后存续——而新列出的模型则采纳端点披露的名称与容量。随后目录会从设置文档读回，因为那才是本页的事实来源。

### 失败情形

端点不可达、拒绝请求或应答的不是模型列表时，按钮旁会显示 Host 自己的诊断信息，而在「模型」页手工编辑目录依然可用。端点应答了但没有模型时会明确说明，而不会打开一个空选择器。如果设置文档在卡片读取之后发生变化，更新会作为过期请求被拒绝，而不会覆盖较新的值，选择器也会保持打开，以免丢失已选项。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节——点击展开</summary>

本包只有一次注册和一次写入。它不贡献任何设置命名空间，也不自带 Host 能力。

### 卡片的位置

卡片以 DeepSeek 设置命名空间为 key，注册进「模型」分区声明的带 key 座位 `settings.models.provider-card`。该分区会为每个提供方行派发一次这个座位，并跳过无人认领的 key，因此本包渲染在 DeepSeek 行内部，而「模型」页完全不知道它的存在。本包的 Host 半边是惰性的：端点询问属于拥有连接事实的适配器族，由 `llm-deepseek` 注册。

### 询问与写入

获取时会调用 `llm/discoverModels` Remote，它只返回候选项元数据，从不写入；端点和凭据由适配器族自行解析，因此这张卡片永远看不到密钥。被确认采纳的内容是唯一的变更：一个替换 `models` 的 `settings.mutate` 路径操作，并以卡片读到的命名空间修订号作为栅栏。本包需要的两个 Remote 命名空间都在它自己的 `inject` 中声明，而卡片拿到的是回调而不是 context。

</details>

<a id="model-experience"></a>
## 模型体验

无。本包是浏览器侧设置界面，不注册任何面向模型的内容。它写入的目录是「模型」页与模型选择器展示的提示性元数据，不会进入提供方请求。

#### KV Cache effect

无；本包既不组装也不发送提供方请求。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

这些限制界定了本卡片服务哪条线路、能询问什么；它们是当前的包约束。

- **只有 DeepSeek 命名空间有刷新卡片**——卡片以 `llm-deepseek` 为 key，这是唯一为已配置线路注册模型发现的适配器族。pi-ai 线路在自己的编辑器里已经有这个动作，而未注册模型发现的适配器族在这里不会渲染卡片。
- **卡片询问的是线路，而不是表单**——它询问 Host 为该线路解析出的端点与凭据，因此在编辑器里输入但尚未保存的端点并不是本动作探测的对象。
- **询问覆盖 OpenAI 兼容的列表格式**——适配器会读取兼容网关提供的 `data` 数组或增强的 `models` 映射；使用其他列表方言的端点会报告它返回了无法解读的内容。
